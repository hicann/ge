# Python Declarative Address Refresh Sample

This sample builds a graph in Python, has ATC load the Python module and run the `declare_launch_args` callback at compile time, then uses ACL Python to load the same OM on a real NPU for two address-refresh rounds with independent device addresses and numeric validation.

## Layout

```text
python
├── CMakeLists.txt                 # Builds the custom OPP registry library and es_custom wheel
├── run.sh                         # Kernel, ES, AIR, ATC, and two-round ACL validation entry point
├── proto/                         # AnnotatedAddCustom operator prototype
└── src/
    ├── build_graph.py             # Python graph builder that writes AIR
    ├── run_model.py               # ACL Python two-round NPU execution
    └── ge/annotated_add_custom.py # Compile-time declare_launch_args callback
```

## Prerequisites and running

Install and configure CANN, BiSheng, LLVM `llvm-objcopy`, ATC, CMake, Python 3/pip, numpy, and a usable NPU.

```bash
source /path/to/cann/set_env.sh
cd examples/custom_op/annotated_args_refresh_add_custom/python
bash run.sh
```

Only these three environment variables are overridable:

- `ADD_CUSTOM_NPU_ARCH`: defaults to `2201` and is passed to BiSheng as `--npu-arch=dav-2201`.
- `SOC_VERSION`: defaults to `Ascend910B1` and is passed to ATC.
- `DEVICE_ID`: defaults to `0` and is passed to the ACL Python runtime.

For example: `ADD_CUSTOM_NPU_ARCH=2201 SOC_VERSION=Ascend910B1 DEVICE_ID=0 bash run.sh`.

## Outputs and compile-time evidence

The script produces these core outputs:

- `build/add_custom.o`: the AI Core binary extracted from the Ascend C kernel.
- `build/opp/op_graph/lib/<os>/<arch>/libcust_opapi.so`: custom OPP registry library (dll on Windows).
- `build/es_output/whl/es_custom-1.0.0-py3-none-any.whl`: Python ES wheel.
- `build/annotated_add.air`: AIR built by the Python graph builder.
- `build/annotated_add.om`: OM generated by ATC.

It also writes the compile log to `build/atc.log` and the real NPU runtime log to `build/runtime.log`. The ATC log must contain:

- `PY_ANNOTATED_ARGS_MODULE_LOADED=1`: the Python callback module was imported at ATC compile time.
- `PY_ANNOTATED_ARGS_CALLBACK_ENTER=1`: ATC entered the `declare_launch_args` callback at compile time.

The Python callback runs only at ATC compile time. At OM runtime, only the generated TaskDef is consumed; Python is neither imported nor called again, so neither marker may appear in the runtime log.

## Two-round address-refresh validation

ACL Python allocates x/y/z device addresses for round 1 with `1 + 2 = 3`, then newly allocates x/y/z addresses for round 2 with `4 + 5 = 9`. The corresponding x, y, and z device addresses must all differ between rounds, and all 8192 `float32` elements are checked with `allclose`. The log reports hexadecimal addresses, first value, expected value, and maximum error for each round; `NPU_TWO_ROUND_VALIDATION=PASS` signals success.

## Callback constraints

`append_input` and `append_output` respectively use the flattened index of their own input/output instance on the current compute node; instances expanded from a dynamic item occupy consecutive indexes. The `AnnotatedArgsContext`, Tensor, workspace, and args builder are borrowed callback-time objects and must not escape the callback. The args builder is consumed by `add_launch` and must not be reused.
